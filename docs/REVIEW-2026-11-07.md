# AgentRouter: Claude and Codex review

Both reviewers independently reviewed Sources, tests, build scripts, Package.swift,
README and architecture/verification documentation. Reviews were sequential and
read-only. Findings below were consolidated by the implementing Codex agent.
The reviewers assessed the version before the fixes described here; they have not
re-reviewed those fixes.

## Security concern requiring separate validation

Claude noted that hook credentials are inherited by controller descendants and that
those descendants are accepted as IPC peers. The current trust boundary is the
local user and controller process tree, not an isolated native hook executable.
An untrusted process inside that tree could potentially forge readiness/modal
events if it also obtains the native session ID. No exploit was run in this review.
Restricting only to direct child PIDs is not a validated fix: legitimate hooks may
run through shells/wrappers. Treat stronger event provenance as unresolved; never
use this review to relax approval or readiness checks.

F7/F8/F9 being enabled by default was not treated as a defect: the user explicitly
requested those global shortcuts. No shortcut behavior was changed.

## Verification of lifecycle fixes

The original installed-Codex startup test failed under `PATH=/usr/bin:/bin`, despite
passing under the shell environment. After assigning the child PATH, the same test
exposed the broken Node 25 dylib dependency. After runtime validation/selection,
the expanded real-Codex Start/Stop/Restart test passed in 7.532 seconds:

```sh
/usr/bin/env PATH=/usr/bin:/bin LC_ALL=C LANG=C \
  AGENTROUTER_NATIVE_TESTS=1 AGENTROUTER_NATIVE_CLI=codex \
  /usr/bin/swift test --filter NativeCLITests/testInstalledCLIsStartupWithoutPrompts
```

All automated lifecycle sessions/projects were disposable. No prompt was sent and
no authentication, hook-trust or permission dialog was accepted. This verifies
startup and lifecycle health, not model-turn completion or notification reliability.
Claude CLI was reviewed statically, not launched in this final regression run.

Installed application build succeeded and `/Applications/AgentRouter.app` was
updated while closed. The actual Project 3 UI lifecycle check then passed:

- Start replaced the previously dead pane with `test-pane`, verified alive after startup.
- Stop, with its confirmation, made `test-pane` dead without any force-stop.
- Start after Stop created `test-pane`; the CLI remained alive.
- Restart, with its confirmation, gracefully stopped `test-pane`, created `test-pane`, and
  reported successful opening of the replacement Terminal target. The widget
  showed Agent Running, verified tmux health and live CLI health afterward.

Project 3 was left running in a fresh conversation in `test-pane`; no prompt was sent.
Project 1 and Project 2 were not stopped or restarted. Terminal.app cannot
be inspected by the available automation tool, so window appearance/focus was not
visually verified; the application's Terminal-opening operation returned success.

An additional output-rendering issue was observed during the UI check: tmux can
emit OSC 8 hyperlink sequences, which the CSI-only renderer currently leaves in
displayed/copied output. Claude had listed this as a hypothesis; the visible
Codex update banner confirmed it. This remains open and was not mixed into the
lifecycle fix.
